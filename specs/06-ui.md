# 06. UI仕様

**デザイン参照**: [`manaflow-ai/cmux`](https://github.com/manaflow-ai/cmux) のmacOSアプリ。左サイドバー型のワークスペース一覧、各項目にプロジェクト名・パス・ブランチ・状態バッジ・通知数を表示する情報密度の高いリスト。CC Pocketのモバイル版はこのモデルを「左ドロワー」として再構成する。

## 6.1 画面一覧

| ID | 画面 | 経路 |
|----|------|------|
| SC-01 | PIN入力画面 | 未認証 or トークン期限切れ |
| SC-02 | メイン画面 | 認証済み |
| SC-03 | 接続エラー画面 | サーバ到達不可（Tailscale未起動等） |
| SC-04 | ロックアウト画面 | PIN5回失敗後 |

## 6.2 SC-01: PIN入力

```
┌──────────────────────┐
│                      │
│      CC Pocket       │
│                      │
│   ┌────────────┐     │
│   │ ●●●●        │     │
│   └────────────┘     │
│                      │
│   [ 1 ][ 2 ][ 3 ]    │
│   [ 4 ][ 5 ][ 6 ]    │
│   [ 7 ][ 8 ][ 9 ]    │
│   [ ← ][ 0 ][決定]    │
│                      │
└──────────────────────┘
```

**仕様**:
- 数字テンキーは画面内描画（OSキーボードを呼ばない）
- 4桁固定（v1）
- 入力中は●●●●、誤りで赤く震える
- 残り試行回数を5回未満で表示

## 6.3 SC-02: メイン画面

```
┌────────────────────────────────────┐
│ ☰  feat-x  🔴 needs input    [⋮]    │ ← Header (固定)
├────────────────────────────────────┤
│                                    │
│  > read README.md                  │ ← Log Area
│                                    │
│  Read 53 lines from README.md      │
│                                    │
│  > use Bash to run `npm test`      │
│                                    │
│  ────────────────────────────────  │
│  ⚠️ ツール実行の承認                  │ ← Approval Banner
│  npm test を実行してよいですか？      │   (条件付き表示)
│                                    │
│  [  許可  ][  拒否  ][常に許可]      │
│  ────────────────────────────────  │
│                                    │
├────────────────────────────────────┤
│ [_______________________] [送信]   │ ← Input Bar (固定)
│ [y][n][1][2][3][Esc][^C]            │ ← Quick Keys (折りたたみ可)
└────────────────────────────────────┘
```

### 6.3.1 Header

- 高さ56px、上部固定
- 左から: `☰`（ドロワー開閉）/ 現在のワークスペース名 / 状態ドット+ラベル / `⋮`（設定メニュー）
- 設定メニュー: 新規ウィンドウ作成 / 設定パネル / ログアウト
- 状態ラベルは状態色とテキストの両方を出す（cmux準拠: "Idle" / "Running" / "Needs input" / "Error"）

### 6.3.2 ドロワー（左サイドバー）

cmuxのvertical tabs UIをモバイル化。`☰`タップで左から60%幅でスライドイン。

```
┌──────────────────────────────────┐
│ ☰  ワークスペース           [+]  │
├──────────────────────────────────┤
│ 📌 main                          │
│    ~/Projects/Git/foo            │
│    main                          │
│    🟢 Idle                       │
├──────────────────────────────────┤
│ ▶ feat-x                  ●3     │  ← active (左に縦バー)
│    ~/Projects/Git/bar            │
│    fix/auth-error-handling       │
│    🔴 Needs input                │
├──────────────────────────────────┤
│   review                         │
│    ~/Projects/Git/baz            │
│    main*                         │
│    🟡 Running                    │
├──────────────────────────────────┤
│   吹き矢                          │
│    ~/Projects/Git/sumiya         │
│    main                          │
│    ⚫ Error                       │
└──────────────────────────────────┘
```

**項目あたりの表示**（cmux準拠）:
- 1行目: ワークスペース名（太字）+ 通知バッジ（赤丸 + 件数、未確認の `awaiting_approval` 等）+ ピンアイコン（任意）
- 2行目: 作業ディレクトリパス（小・グレー）
- 3行目: ブランチ名（小・グレー、`*`で未コミット示唆）
- 4行目: 状態ドット + ラベル（"Idle" / "Running" / "Needs input" / "Error"）

**インタラクション**:
- アクティブ項目は左端に縦線、わずかな背景色変化
- タップでメイン画面に該当ワークスペースを表示、ドロワーは自動クローズ
- 長押しで rename / close メニュー（v1スコープ外、UIだけ予約）
- `+` ボタン: 新規ワークスペース作成（v1ではtmux内で手動`claude`起動が前提なので「新規tmux window作成のみ」を実施）

**ソート**: 通知バッジあり → アクティビティ新しい順。ピン留めは常に最上段（v2スコープ）。

### 6.3.3 状態表記の統一（cmux準拠）

WindowStateとUIラベルの対応:

| Window State | ドット色 | UIラベル | cmux相当 |
|--------------|--------|---------|---------|
| `idle` | 🟢 | Idle | "Claude is idle" |
| `streaming` | 🟡 | Running | "Claude is running" |
| `awaiting_approval` | 🔴 | Needs input | "Claude is waiting for your input" |
| `error` | ⚫ | Error | エラー表示 |

通知バッジは `awaiting_approval` 件数（同一ウィンドウは最大1件、ドロワー全体で複数windowの合算は数字バッジで表示）。

### 6.3.3 Log Area

- メイン領域、上下スクロール
- 出力チャンクは到着順に追加。色分け:
  - ユーザ入力: 緑（行頭`> `）
  - Claude応答: 白
  - ツール出力: 灰
  - エラー: 赤
- ANSIエスケープは最小限の解釈（Bold, 4色程度）でOK
- 自動スクロール: 末尾追従中はスクロール固定。ユーザが上方向にスクロールした瞬間に追従解除、最下部に戻る`↓`ボタン表示

### 6.3.4 Approval Banner（条件付き表示）

- `state === 'awaiting_approval'` のときのみLog Areaの末尾直前に挿入
- Log Areaの一部としてスクロールに追従（固定オーバーレイにしない: 文脈と一緒に読みたいため）
- 3ボタン:
  - `許可` → `action: "yes"`
  - `拒否` → `action: "no"`
  - `常に許可` → `action: "always"`
- ボタンタップ後はバナーが消えてLog Areaに承認結果が記録される（"許可しました"等のクライアント側ログ）
- バナー表示中は通常の入力欄をdisabledにし、placeholder「承認待ちです」表示

### 6.3.5 Input Bar

- 下部固定、高さ可変（複数行対応）
- 送信:
  - スマホ: 送信ボタンタップ
  - 物理キーボード接続時: Enterで送信、Shift+Enterで改行
- 送信後は入力欄クリア
- 送信中は送信ボタンが0.5秒間グレーに

### 6.3.6 Quick Keys（折りたたみ可）

- Input Barの直下にコンパクトボタン群
- ボタン: `y` `n` `1` `2` `3` `Esc` `Ctrl+C` `↑` `↓` `Tab`
- タップで該当キーストロークを `/keys` POSTで送信
- デフォルト折りたたみ、上向き矢印アイコンで展開

## 6.4 SC-03: 接続エラー画面

```
┌──────────────────────┐
│                      │
│         ⚠️           │
│  サーバに接続できません  │
│                      │
│  ・Tailscale起動済?  │
│  ・サーバ起動済?     │
│                      │
│  [   再試行   ]       │
│                      │
└──────────────────────┘
```

**仕様**:
- 接続失敗から3秒以内に表示
- 自動リトライ: 5秒、15秒、30秒、60秒（指数バックオフ）
- 再試行ボタンで即時再接続

## 6.5 SC-04: ロックアウト画面

```
┌──────────────────────┐
│                      │
│         🔒           │
│  ロックされています    │
│                      │
│  あと 8:42 後に再試行  │
│                      │
└──────────────────────┘
```

**仕様**:
- カウントダウン表示（mm:ss）
- 0になったら自動でSC-01へ遷移

## 6.6 グローバル挙動

### 6.6.1 通知（PWA）

- 承認待ち遷移時にService Workerから通知発火
- 通知本文: 「[w0 main] 承認待ち: npm test を実行してよいですか？」
- タップで該当ウィンドウを開いた状態でPWAを起動

### 6.6.2 ハプティクス

- iOSの`navigator.vibrate`は不可なので、v1ではなし
- v2ネイティブ化時に検討

### 6.6.3 ライト/ダークモード

- `prefers-color-scheme`に追従。明示切替は持たない（v1）

### 6.6.4 アクセシビリティ

- フォントサイズはOS設定追従（rem単位）
- ボタンは最小44x44pt（iOS HIG準拠）
- VoiceOverはv1スコープ外（自分専用前提）
